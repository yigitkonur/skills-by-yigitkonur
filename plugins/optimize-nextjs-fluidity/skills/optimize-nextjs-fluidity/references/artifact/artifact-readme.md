# Artifact README — planted into `nextjs-enhancement/README.md`

Copy this file's fenced body **verbatim** into `nextjs-enhancement/README.md` at Phase 2,
before dispatching any agent. Every agent reads it as the shared format authority, which
keeps prompts lean and output uniform.

```markdown
# nextjs-enhancement

Generated by the `optimize-nextjs-fluidity` skill. This folder is the durable record of
one optimization run: what the repo looked like, what applied to it, what was found, what
was planned, and what was done.

## Layout

```
nextjs-enhancement/
├── README.md                  this file — the format authority
├── 00-recon.md                repo profile: versions, capability probe, inventory
├── 01-applicability.md        per-domain verdicts; what was deliberately withheld
├── findings/<domain>/NN-*.md  audit evidence, one issue per file
├── tasks/00-INDEX.md          the plan: order, dependencies, waves, status
├── tasks/NN-<verb-object>.md  one file per task — the executable unit
└── 02-completion-report.md    what actually happened
```

## Reading order

1. `02-completion-report.md` — what changed and what needs you.
2. `tasks/00-INDEX.md` — the full plan and its ordering.
3. An individual task file — evidence, exact change, verification, rollback.
4. `findings/` — raw evidence behind a task.
5. `00-recon.md` / `01-applicability.md` — why a practice was or wasn't in scope.

## Conventions

**Task status** — `pending` · `in-progress` · `done` · `blocked` · `blocked-needs-human` ·
`wontfix`. Nothing else parses.

**Severity** — `critical` (removed surface in use, build/runtime error, user-visible
breakage) · `major` (P0 practice absent or misconfigured for this archetype) · `minor`
(deprecated-but-working, unadopted stable opt-in) · `informational` (deliberate divergence
worth noting; never a task by itself).

**Reversibility** — `fully-reversible` (delete a line and it's gone) ·
`component-level-revert` (bounded, mechanical) · `migration-required` (one-way door;
never auto-applied — it is prepared for a human).

**Ordinals encode dependencies**, not discovery order. Task `05` never precedes something
it depends on.

**Evidence is literal.** `file:line` plus the exact matched text, with the command that
found it. Paraphrase is not evidence.

## Guarantees this run made

- Nothing was recommended that the installed Next.js does not support — availability was
  probed against `node_modules`, not inferred from a version number.
- No one-way door was executed automatically.
- Every applied task was verified by running its own check; failures were reverted and
  reported with output.
- Nothing was pushed, merged, or deployed. Dependencies and lockfiles were untouched.
- Practices the repo already follows correctly were not re-proposed.

## Re-running

A later run creates a **new** dated folder rather than overwriting this one. Keep this
directory as the baseline; the withheld list in `01-applicability.md` is the reason to
re-run after a Next.js upgrade.

Regenerate status at any time:

```bash
python3 scripts/status-report.py nextjs-enhancement/
```
```

## Why plant it

Three reasons this file exists rather than repeating the format in every prompt:

1. **One authority.** Agents match against a file on disk, not against N copies of a spec
   that drift apart.
2. **Leaner briefs.** A prompt says "follow `nextjs-enhancement/README.md`" instead of
   restating the vocabulary.
3. **It outlives the run.** A human opening the folder six weeks later gets the conventions
   without the session.

Plant it before dispatch. An agent that starts before the README exists has no format
authority to match.
