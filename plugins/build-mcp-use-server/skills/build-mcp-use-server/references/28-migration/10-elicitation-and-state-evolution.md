# Interactive Elicitation & State Evolution

*Read this when migrating from deprecated `ctx.elicit()` or `ctx.sample()` to official mcp-use v2 protocol primitives (`inputRequired`, `createRequestStateCodec`).*

In early experimental betas of `mcp-use`, interactive human-in-the-loop flows relied on an imperative `await ctx.elicit()` method that assumed a paused, long-lived server stack frame, and server-side LLM sampling via `ctx.sample()`. 

**In `mcp-use v2.4.3+` (#2409), `ctx.elicit()` was permanently removed from `RequestContext`.** Server-side `ctx.sample()` was likewise eliminated in favor of deterministic tools. Official `mcp-use v2` aligns directly with the MCP `input_required` specification: tools operate within an entirely **stateless re-entry lifecycle**, requesting human form or URL inputs via `inputRequired()`, validating submissions via `inputResponse()` and `acceptedContent()`, and evolving state across multi-turn rounds using HMAC-signed tokens generated by `createRequestStateCodec`.

---

## At a Glance: Elicitation & State Evolution Diff

| Aspect / Primitive | Deprecated Beta (`ctx.elicit` / `ctx.sample`) | Canonical v2 Protocol Specification | Impact / Action |
|---|---|---|---|
| **Elicitation Method** | `await ctx.elicit(key, message, schema)` | `return inputRequired({ inputRequests: { [key]: inputRequired.elicit(...) } })` | Replace method call with returned `InputRequiredResult` envelope |
| **Execution Flow** | Assumed suspended JavaScript thread | Stateless re-entry: handler executes from the top on each client submission | Make handler re-entrant and idempotent; side effects execute only after validation |
| **Response Inspection** | Return value of `await ctx.elicit()` | `inputResponse(ctx.inputResponses, key)` | Check `.kind` (`"missing"` vs `"elicit"`) and `.action` (`"accept"`, `"decline"`, `"cancel"`) |
| **Payload Validation** | Automatic return value assignment | `acceptedContent(ctx.inputResponses, key, schema)` | Validates submission against Standard Schema (Zod v4); returns typed data or `undefined` |
| **URL Mode Elicitation** | Ad-hoc `{ url }` option in `ctx.elicit` | `inputRequired.elicitUrl({ message, url })` | Client opens external browser redirect (OAuth handoff, credentials, checkout) |
| **State Across Turns** | Module-level `new Map()`, Redis sessions, or `ctx.session` | HMAC-signed `createRequestStateCodec<T>` carried in `requestState` | Cryptographically signed, tamper-proof state round-trips without server memory leaks |
| **Server Verification** | None; trusted process memory | `new MCPServer({ requestState: { verify: codec.verify } })` | Tampered or expired state tokens are rejected before handler invocation |
| **Model Sampling** | `await ctx.sample({ prompt })` | **Removed**; client/host LLM generates; server provides deterministic tools | Eliminate server LLM generation; return structured data for the host model |

## The Stateless Re-Entry Mental Model

Understanding the execution lifecycle is essential when migrating from `ctx.elicit()`:

```
Turn 1: Initial Invocation
   Host calls Tool ──► Tool Handler runs from top
                            │
                            ├─► Checks inputResponse(ctx.inputResponses, "key") -> kind: "missing"
                            │
                            └─► Returns inputRequired({
                                  inputRequests: { "key": inputRequired.elicit(...) },
                                  requestState: await codec.mint(initialState)
                                })
                                  │
                                  ▼
                            Client prompts User with Form / URL

Turn 2: User Submits Form
   Host calls Tool ──► Tool Handler runs from top AGAIN (fresh request)
   (same arguments)         │
                            ├─► ctx.requestState<T>() resolves verified token payload
                            │
                            ├─► inputResponse(ctx.inputResponses, "key") -> kind: "elicit", action: "accept"
                            │
                            ├─► acceptedContent(ctx.inputResponses, "key", schema) -> typed data
                            │
                            └─► Side effects execute safely; returns CallToolResult
```

> **Key Rule**: Because the handler runs from the beginning on every round, **never perform permanent side effects (DB writes, charges, emails) before `acceptedContent()` returns validated data**.

## The Core v2 Elicitation Primitives

All elicitation primitives are exported directly from `mcp-use` root:

```typescript
import {
  inputRequired,
  inputResponse,
  acceptedContent,
  createRequestStateCodec,
} from "mcp-use";
```

### 1. `inputRequired({ inputRequests, requestState? })`
Constructs the terminal `InputRequiredResult` envelope returned by your tool callback. Takes a dictionary of input requests keyed by a stable identifier.

### 2. Form Mode: `inputRequired.elicit({ message, requestedSchema })`
Instructs the host to render an interactive form.
- `message`: User-facing prompt or instructions displayed above the form fields.
- `requestedSchema`: Standard Schema (Zod v4 object) defining the fields. Must be a **flat object schema** (nested objects or arrays are rejected by most host form renderers).

### 3. URL Mode: `inputRequired.elicitUrl({ message, url })`
Instructs the host to open an external URL in the user's browser. Used for third-party OAuth handoffs, external payment gateways, or credential capture.

### 4. `inputResponse(ctx.inputResponses, key)`
Inspects whether the user interacted with the specified key in the current turn:
- `{ kind: "missing" }`: The key was not answered in this round (initial turn or another form answered).
- `{ kind: "elicit", action: "accept" }`: User submitted the form. Proceed to validate data.
- `{ kind: "elicit", action: "decline" }`: User clicked "Decline" / "Cancel".
- `{ kind: "elicit", action: "cancel" }`: User dismissed the modal or escaped the dialog.

### 5. `acceptedContent(ctx.inputResponses, key, schema)`
Validates the client's submitted form data against your schema:
- Returns `T` (the validated, typed object) if the user accepted and the payload passed schema validation.
- Returns `undefined` if the response was missing, declined, cancelled, or failed schema validation.

### 6. Cryptographic State Codec: `createRequestStateCodec<T>`
Mints and verifies HMAC-signed state tokens carried across turns:
- Requires a secret key of **at least 32 bytes** (string or `Uint8Array`).
- Automatically enforces expiration (`ttlSeconds`, defaults to 600 seconds / 10 minutes).
- Wire token is tamper-evident: modifying the string invalidates the HMAC signature.

## Runnable Before & After Code Transformation

### Before: Deprecated `ctx.elicit()` & In-Memory Map

In legacy or beta code, developers relied on `ctx.elicit()` and module-level variables to hold wizard state, expecting a blocking pause:

```typescript
// Deprecated Beta: ctx.elicit() (removed in v2.4.3), in-memory Map, ctx.sample()
import { MCPServer } from "mcp-use";
import { z } from "zod";

const server = new MCPServer({ name: "legacy-server", version: "1.0.0" });

// ANTI-PATTERN: In-memory state map leaks memory and breaks across multi-instance nodes
const pendingTransactions = new Map<string, { to: string; amount: number }>();

server.tool(
  {
    name: "transfer-funds",
    description: "Transfer money to another account",
    schema: z.object({
      toAccount: z.string(),
      amount: z.number(),
    }),
  },
  async ({ toAccount, amount }, ctx) => {
    // 1. FAILS IN v2.4.3+: TypeError: ctx.elicit is not a function
    const userConfirmation = await (ctx as any).elicit({
      message: `Confirm transfer of $${amount} to ${toAccount}?`,
      schema: z.object({ confirmed: z.boolean() }),
    });

    if (!userConfirmation.confirmed) {
      return { content: [{ type: "text", text: "Transfer cancelled by user." }] };
    }

    // 2. FAILS IN v2: TypeError: ctx.sample is not a function
    const summary = await (ctx as any).sample({
      prompt: `Generate a receipt message for sending $${amount} to ${toAccount}`,
    });

    // 3. Side effects executed
    await db.transfer(toAccount, amount);

    return { content: [{ type: "text", text: summary }] };
  }
);
```

### After: Canonical mcp-use v2 Elicitation & RequestState Codec

In canonical `mcp-use v2`, state is carried securely in signed tokens, input responses are checked on re-entry, and side effects execute only after validated confirmation:

```typescript
// Canonical mcp-use v2: Stateless re-entry, inputRequired, RequestState, tamper protection
// server.ts
import {
  MCPServer,
  inputRequired,
  inputResponse,
  acceptedContent,
  createRequestStateCodec,
} from "mcp-use";
import { z } from "zod";

// State payload carried securely across turns
type TransferState = {
  stage: "awaiting-confirmation";
  toAccount: string;
  amount: number;
  nonce: string;
};

// 32-byte signing key loaded securely from environment (throws RangeError if < 32 bytes)
const STATE_SECRET = process.env.REQUEST_STATE_SECRET || "secure-signing-secret-at-least-32-bytes-long!";

const transferCodec = createRequestStateCodec<TransferState>({
  key: STATE_SECRET,
  ttlSeconds: 300, // 5-minute timeout window
});

const server = new MCPServer({
  name: "financial-mcp-server",
  version: "2.0.0",
  basePath: "/mcp",
  // Register cryptographic verifier on server instance
  requestState: { verify: transferCodec.verify },
});

// Schema for the elicitation form
const ConfirmationFormSchema = z.object({
  approved: z.boolean().describe("Explicit user approval checkbox"),
  memo: z.string().max(100).optional().describe("Optional transfer note for records"),
});

export const transferFunds = server.tool(
  {
    name: "transfer-funds",
    title: "Transfer Funds",
    description: "Transfer money to another account with mandatory interactive confirmation",
    inputSchema: z.object({
      toAccount: z.string().describe("Target account number"),
      amount: z.number().positive().describe("Amount in USD to transfer"),
    }),
    outputSchema: z.object({
      transactionId: z.string(),
      status: z.string(),
      toAccount: z.string(),
      amount: z.number(),
    }),
    annotations: {
      destructiveHint: true,
      idempotentHint: false,
    },
  },
  async ({ toAccount, amount }, ctx) => {
    // 1. Client capability check
    if (!ctx.client.capabilities().elicitation?.form) {
      return {
        isError: true,
        content: [{ type: "text", text: "Client does not support interactive form elicitation." }],
      };
    }

    // 2. Read state and user response for this turn
    const verifiedState = ctx.requestState<TransferState>();
    const response = inputResponse(ctx.inputResponses, "transfer-confirmation");

    // 3. Handle explicit user cancellation or dismissal
    if (response.kind === "elicit" && response.action !== "accept") {
      return {
        isError: true,
        content: [{ type: "text", text: `Transfer cancelled by user (${response.action}).` }],
      };
    }

    // 4. Verify parameter tampering across rounds
    if (
      verifiedState !== undefined &&
      (verifiedState.toAccount !== toAccount || verifiedState.amount !== amount)
    ) {
      return {
        isError: true,
        content: [{ type: "text", text: "Security alert: Transfer parameters altered between confirmation rounds." }],
      };
    }

    // 5. Validate accepted form submission
    const confirmation = acceptedContent(ctx.inputResponses, "transfer-confirmation", ConfirmationFormSchema);

    // 6. Turn 1 or Missing Submission: Request input with HMAC-signed state
    if (verifiedState === undefined || confirmation === undefined) {
      return inputRequired({
        inputRequests: {
          "transfer-confirmation": inputRequired.elicit({
            message: `Please confirm: Transfer $${amount.toFixed(2)} to account ${toAccount}?`,
            requestedSchema: ConfirmationFormSchema,
          }),
        },
        requestState: await transferCodec.mint({
          stage: "awaiting-confirmation",
          toAccount,
          amount,
          nonce: crypto.randomUUID(),
        }),
      });
    }

    // 7. Verify user checked the approval box
    if (!confirmation.approved) {
      return {
        isError: true,
        content: [{ type: "text", text: "Transfer declined by user." }],
      };
    }

    // 8. Execute side effects ONLY after verified state and validated user submission
    const transactionId = `tx_${crypto.randomUUID().slice(0, 8)}`;
    // await db.transfer({ toAccount, amount, memo: confirmation.memo });

    return {
      content: [
        {
          type: "text",
          text: `Successfully transferred $${amount.toFixed(2)} to account ${toAccount}. Transaction ID: ${transactionId}.`,
        },
      ],
      structuredContent: {
        transactionId,
        status: "completed",
        toAccount,
        amount,
      },
    };
  }
);

export default server;
```

## URL Mode: External Authentication & Redirects

When an operation requires external user interaction (e.g. connecting a GitHub account, approving a stripe payment, or entering an MFA token), use `inputRequired.elicitUrl()`:

```typescript
export const connectExternalService = server.tool(
  {
    name: "connect-service",
    description: "Link third-party account via browser authorization",
    inputSchema: z.object({ accountId: z.string() }),
    outputSchema: z.object({ linked: z.boolean() }),
  },
  async ({ accountId }, ctx) => {
    const response = inputResponse(ctx.inputResponses, "oauth-redirect");

    if (response.kind === "elicit") {
      // User returned from browser redirect
      const isLinked = await checkThirdPartyLink(accountId);
      if (isLinked) {
        return {
          content: [{ type: "text", text: "External service successfully linked." }],
          structuredContent: { linked: true },
        };
      }
      return {
        isError: true,
        content: [{ type: "text", text: "Authorization was not completed in the browser." }],
      };
    }

    // Generate external authorization URL with state token
    const authUrl = `https://auth.example.com/oauth/authorize?account=${encodeURIComponent(accountId)}`;

    return inputRequired({
      inputRequests: {
        "oauth-redirect": inputRequired.elicitUrl({
          message: "Please authorize access in your browser to proceed.",
          url: authUrl,
        }),
      },
    });
  }
);
```

## Anti-Patterns and Common Elicitation Traps

| Anti-Pattern | Root Mechanism & Failure Mode | Canonical v2 Fix |
|---|---|---|
| **Calling `ctx.elicit()` or `ctx.sample()`** | Both methods were permanently removed in v2.4.3 (#2409). Triggers runtime `TypeError: ctx.elicit is not a function`. | Return `inputRequired()` envelope and read submissions with `inputResponse()` / `acceptedContent()`. Remove `ctx.sample()`. |
| **Executing Side Effects on Turn 1** | Performing database writes or API mutations before elicitation executes the action *every time* the tool is prompted, even if the user declines. | Place side effects strictly after `acceptedContent()` returns a validated, approved object. |
| **Infinite Elicitation Loop** | Handler returns `inputRequired()` on every re-entry without inspecting `ctx.inputResponses` or `acceptedContent()`. The client prompts the user repeatedly. | Check `acceptedContent()` first. If present and valid, finish the tool and return `CallToolResult`. |
| **Using Secrets `< 32` Bytes with `createRequestStateCodec`** | Passing a short key (e.g. `"my-secret"`) throws `RangeError: Key must be at least 32 bytes` on server startup. | Provide a cryptographically secure key of at least 32 characters/bytes (`process.env.REQUEST_STATE_SECRET`). |
| **Using Nested Schemas in `inputRequired.elicit`** | Supplying nested objects (`z.object({ address: z.object({ city: z.string() }) })`) causes host form renderers to crash or reject the schema. | Use flat object schemas for form elicitation. |
| **Using RequestState as the Sole Authorization Barrier** | Request state tokens are signed, not encrypted. Clients can inspect the payload. Relying solely on `requestState` without re-verifying `ctx.auth` can allow privilege escalation. | Always re-verify `ctx.auth.user.id` and resource ownership alongside `ctx.requestState<T>()`. |
| **Changing the String Key Between Rounds** | Calling `inputResponse(ctx.inputResponses, "key-2")` when `inputRequired` registered `"key-1"` returns `kind: "missing"`, restarting the wizard. | Use a single constant string key (e.g. `"approval"`) for both registration and reading. |
