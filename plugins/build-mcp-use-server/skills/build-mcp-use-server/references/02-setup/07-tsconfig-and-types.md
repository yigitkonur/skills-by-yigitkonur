# tsconfig and types

*Read this to understand TypeScript configuration and type generation in v2.*

## tsconfig.json

Scaffolded projects include a standard ESM + source-map config:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2020"],
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "outDir": "./dist",
    "rootDir": ".",
    "strict": true,
    "skipLibCheck": true,
    "esModuleInterop": true,
    "resolveJsonModule": true
  },
  "include": ["index.ts", "mcp-env.d.ts"],
  "exclude": ["node_modules", ".mcp-use"]
}
```

Key points:
- **`module: "NodeNext"`** — ESM output
- **`"mcp-env.d.ts"` in `include`** — bridges server tools to views
- **`strict: true`** — enforces type safety
- **`declaration: true`** — generates `.d.ts` files (needed for views)

Do not use `skipLibCheck: false` or weaken strict mode without reason.

## mcp-env.d.ts

Auto-generated by `npm run typecheck` (or `mcp-use typecheck`). Never edit by hand.

```typescript
// Generated by mcp-use. Do not edit.
import "mcp-use/vite-client";

declare module "mcp-use/react" {
  interface Register {
    tools: typeof import("./index.js");
  }
}

export {};
```

**Purpose:** Creates a TypeScript bridge so views can import and type-check tools from the server entry. When you add `export const myTool = server.tool(...)` in `index.ts`, views gain full type hints for `useCallTool("myTool")`.

**Refresh after:**
- Adding/removing tools, resources, or prompts
- Changing tool schemas
- Changing output types

**Do not commit** — regenerate locally on every dev cycle. CI should fail if stale (`npm run typecheck` catches it).

## React setup (mcp-apps template)

Views use `mcp-use/react` hooks with full type safety:

```tsx
// views/my-view/view.tsx
import { useCallTool } from "mcp-use/react";

export default function MyView() {
  const { callTool, isPending } = useCallTool("myTool");
  // TypeScript knows myTool exists (from mcp-env.d.ts)
  // and checks input/output types automatically
}
```

If the tool does not exist or schema changed, TypeScript errors immediately.

## Standard Schema (Zod v4)

All schemas must use Standard Schema (Zod v4). mcp-env.d.ts allows TypeScript to infer input/output types from schema definitions:

```typescript
import { z } from "zod";

const myTool = server.tool(
  {
    name: "add",
    inputSchema: z.object({
      a: z.number(),
      b: z.number(),
    }),
    outputSchema: z.object({
      result: z.number(),
    }),
  },
  async ({ a, b }, ctx) => ({
    content: [{ type: "text", text: `${a} + ${b}` }],
    structuredContent: { result: a + b },
  })
);
```

TypeScript infers:
- Input: `{ a: number; b: number }`
- Output: `{ result: number }`

Views calling `myTool` will see these types in `useCallTool`.

## Workflow

```bash
# After any schema change:
npm run typecheck

# Check for type errors:
npm run dev
# TypeScript errors print; fix and save

# Build (also typechecks):
npm run build
```

CI should enforce `npm run typecheck` before build/deploy.
