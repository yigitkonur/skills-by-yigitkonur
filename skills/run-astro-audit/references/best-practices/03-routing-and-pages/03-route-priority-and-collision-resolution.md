# Master Astro Route Priority and Collision Rules

> **Context:** Routing & Pages | **Impact:** High | **Target:** Astro 4 / Astro 5

## 1. Why We Do This

When multiple files could potentially match the same incoming URL (e.g. `/posts/new` vs `/posts/[id].astro` vs `/[...slug].astro`), Astro enforces a strict, deterministic route priority order to resolve the conflict without runtime ambiguity or silent overrides.

## 2. How It Differs From Classic React / Next.js

Next.js warns or errors on conflicting parallel routes in some versions, or uses internal scoring algorithms. Astro defines an explicit, published 8-tier hierarchy:

1. **Reserved internal routes:** `_astro/`, `_server_islands/`, `_actions/`.
2. **Segment depth / specificity:** Routes with more path segments take precedence over shallower rest routes.
3. **Static routes:** Routes without parameters (e.g. `posts/create.astro`) take precedence over dynamic routes.
4. **Named dynamic parameters:** `posts/[page].astro` takes precedence over rest parameters `posts/[...slug].astro`.
5. **Prerendered dynamic routes:** Prerendered routes take precedence over server on-demand dynamic routes.
6. **Endpoints:** Endpoint files (`.ts`, `.js`) take precedence over page components (`.astro`).
7. **File-based routes:** Take precedence over configured redirects in `astro.config.mjs`.
8. **Alphabetical fallback:** Ordered by Node environment locale.

## 3. Common Mistakes & Anti-Patterns

Developers often expect a catch-all route at the project root (`src/pages/[...slug].astro`) to serve as a 404 handler or expect configured redirects to override an existing static page. A physical file always takes precedence over a redirect rule.

### ❌ Bad Practice / Anti-Pattern

```javascript
// astro.config.mjs
// Attempting to redirect /about to /company when src/pages/about.astro exists
export default defineConfig({
  redirects: {
    '/about': '/company', // Ignored because src/pages/about.astro exists!
  },
})
```

### ✅ Best Practice / Idiomatic

```astro
---
// src/pages/posts/new.astro (Static route)
// Takes absolute precedence over src/pages/posts/[id].astro
---
<h1>Create New Post</h1>
```

```astro
---
// src/pages/posts/[id].astro (Dynamic named parameter)
// Takes precedence over src/pages/posts/[...slug].astro,
// but leaves /posts/new to new.astro.
import type { GetStaticPaths } from "astro";
export const getStaticPaths = (() => {
  return [{ params: { id: "1" } }, { params: { id: "2" } }];
}) satisfies GetStaticPaths;
const { id } = Astro.params;
---
<h1>Post #{id}</h1>
```

## 4. Verification & Audit

Run the build command and inspect the route manifest generated by Astro CLI:

```bash
pnpm astro build --verbose
```

Verify that specialized routes (like `/posts/new`) generate distinct static files without being shadowed by dynamic parameter paths.
