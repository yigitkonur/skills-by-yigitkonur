# tsconfig and types

*Read this to understand TypeScript configuration and type generation in v2.*

## tsconfig.json

All three `create-mcp-use-app` templates (`mcp-server`, `mcp-apps`, `blank`) generate the identical config:

```json
{
  "compilerOptions": {
    "target": "ES2024",
    "jsx": "react-jsx",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2024", "DOM", "DOM.Iterable"],
    "strict": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true,
    "noEmit": true,
    "noUncheckedSideEffectImports": true
  },
  "include": ["index.ts", "mcp-env.d.ts", "src/**/*", "views/**/*", "server.ts", ".mcp-use/**/*.d.ts"],
  "exclude": ["node_modules", "dist"]
}
```

Key points:
- **`module`/`moduleResolution: "NodeNext"`** — ESM, matches `"type": "module"`
- **`lib: [..., "DOM", "DOM.Iterable"]`** — required even for tool-only servers because `mcp-env.d.ts` and view type-checking pull in DOM lib types; do not narrow this to drop DOM
- **`jsx: "react-jsx"`** — present in every template, including `mcp-server` and `blank` (not just `mcp-apps`), so views can be added later without a tsconfig edit
- **`noEmit: true`** — tsc is typecheck-only in v2. Build output is produced by a separate Vite pipeline through `mcp-use build`, not by `tsc` emission. Do **not** add `declaration`, `declarationMap`, `sourceMap`, `outDir`, or `rootDir` — none of these are in the shipped template and `noEmit: true` makes them no-ops or conflicting
- **`"mcp-env.d.ts"` in `include`** — bridges server tools to views
- **`".mcp-use/**/*.d.ts"` in `include`** — picks up other CLI-generated declaration files in the workspace directory
- **`strict: true`** — enforces type safety

Do not set `skipLibCheck: false` or weaken strict mode without reason. Do not reintroduce `resolveJsonModule` or emit-related options — they are not part of the real template and add nothing under `noEmit: true`.

## mcp-env.d.ts

Auto-generated by `npm run typecheck` (or `mcp-use typecheck`). Never edit by hand.

```typescript
// Generated by mcp-use. Do not edit.
import "mcp-use/vite-client";

declare module "mcp-use/react" {
  interface Register {
    tools: typeof import("./index.js");
  }
}

export {};
```

**Purpose:** Creates a TypeScript bridge so views can import and type-check tools from the server entry. When you add `export const myTool = server.tool(...)` in `index.ts`, views gain full type hints for `useCallTool("myTool")`.

**Refresh after:**
- Adding/removing tools, resources, or prompts
- Changing tool schemas
- Changing output types

**Do not commit** — regenerate locally on every dev cycle. CI should fail if stale (`npm run typecheck` catches it).

## React setup (mcp-apps template)

Views use `mcp-use/react` hooks with full type safety:

```tsx
// views/my-view/view.tsx
import { useCallTool } from "mcp-use/react";

export default function MyView() {
  const { callTool, isPending } = useCallTool("myTool");
  // TypeScript knows myTool exists (from mcp-env.d.ts)
  // and checks input/output types automatically
}
```

If the tool does not exist or schema changed, TypeScript errors immediately.

## Standard Schema (Zod v4)

All schemas must use Standard Schema (Zod v4). mcp-env.d.ts allows TypeScript to infer input/output types from schema definitions:

```typescript
import { z } from "zod";

const myTool = server.tool(
  {
    name: "add",
    inputSchema: z.object({
      a: z.number(),
      b: z.number(),
    }),
    outputSchema: z.object({
      result: z.number(),
    }),
  },
  async ({ a, b }, ctx) => ({
    content: [{ type: "text", text: `${a} + ${b}` }],
    structuredContent: { result: a + b },
  })
);
```

TypeScript infers:
- Input: `{ a: number; b: number }`
- Output: `{ result: number }`

Views calling `myTool` will see these types in `useCallTool`.

## Workflow

```bash
# After any schema change, regenerate declarations and run tsc --noEmit:
npm run typecheck

# Start the development server with HMR (does not run tsc):
npm run dev

# Produce the Vite build (does not run tsc):
npm run build
```

Neither `dev` nor `build` is a substitute for `typecheck`; both use Vite transforms rather than the TypeScript compiler. CI should enforce `npm run typecheck` before build/deploy.
