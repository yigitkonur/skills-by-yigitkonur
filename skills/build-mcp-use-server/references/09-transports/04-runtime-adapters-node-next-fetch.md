# Runtime adapters: Node, Next.js, and Fetch

*Read this when deploying to a specific runtime.*

All v2 servers export `server.fetch` (Web-standard Fetch API). Runtimes that natively support Fetch use it directly; others need a bridge.

## Node.js HTTP server

Use `toNodeHandler(server)` from `mcp-use/node`:

```typescript
import { MCPServer } from "mcp-use";
import { toNodeHandler } from "mcp-use/node";
import { createServer } from "http";

const server = new MCPServer({ name: "my-server", version: "1.0.0" });

// Register tools, resources, prompts

const nodeHandler = toNodeHandler(server);
const httpServer = createServer((req, res) => {
  nodeHandler(req, res);
});

httpServer.listen(3000, () => {
  console.log("Server listening on http://localhost:3000");
});
```

`toNodeHandler` converts `server.fetch(request)` to the Node.js `(req, res, parsedBody?) => Promise<void>` signature. View assets are served from `.mcp-use/build/` (set via `MCP_URL` at build time).

## Next.js App Router (drop-in)

Use `withMcpUse()` config wrapper + `createNextHandler()`:

**`next.config.ts`:**
```typescript
import { withMcpUse } from "mcp-use/next";

export default withMcpUse(nextConfig, {
  entry: "./mcp-server.ts",
  basePath: "/api/mcp",
});
```

**`mcp-server.ts` (server export, NOT calling listen()):**
```typescript
import { MCPServer } from "mcp-use";

const server = new MCPServer({
  name: "my-next-app",
  version: "1.0.0",
  basePath: "/api/mcp",
});

// Register tools, resources, prompts

export default server;
```

**`app/api/mcp/[[...path]]/route.ts` (optional; autogenerated if omitted):**
```typescript
import server from "@/mcp-server";
import { createNextHandler } from "mcp-use/next";

export const { GET, POST, DELETE, OPTIONS } = createNextHandler(server);
```

`withMcpUse()` integrates View compilation into Next.js build; View assets mount at `{basePath}/_mcp-use/views/`. The optional route handler lets you customize the handler (e.g., add logging, pre-checks).

### Standalone beside Next.js (alternative topology)

Instead of embedding the MCP server inside a Next.js Route Handler, run it as a separate process next to the Next.js app, owning its own HTTP server and port:

```bash
mcp-use dev --mcp-dir src/mcp --port 3001    # development
mcp-use build --mcp-dir src/mcp             # production build
mcp-use start                                # production run
```

Use `--path`, `--entry`, and `--views-dir` flags to point at a split monorepo layout where the MCP server code does not live at the Next.js project root. Choose Standalone when the MCP server needs independent scaling/deployment from the Next.js app, or when the app itself is not on Next.js's Route Handler request path (e.g., static export). Choose Embedded (above) when the MCP server should deploy and scale as part of the Next.js app with no second process to manage. See the "Next.js" server doc page for the full Standalone verification checklist.

## Fetch API (Edge, Cloudflare Workers, Deno, etc.)

Export `server.fetch` directly or mount via platform-specific router:

**Cloudflare Workers (wrangler.toml):**
```toml
main = "src/index.ts"
compatibility_date = "2024-12-01"

[env.production]
build.environment = [{ name = "MCP_URL", value = "https://your-worker.dev/mcp" }]

[[env.production.assets.bindings]]
binding = "ASSETS"
path = "dist/.mcp-use/build/views"
```

**`src/index.ts`:**
```typescript
import { MCPServer } from "mcp-use";

const server = new MCPServer({ name: "worker-server", version: "1.0.0" });
// Register tools, resources, prompts
export default {
  fetch: server.fetch,
  assets: ASSETS,
};
```

**Hono:**
```typescript
import { Hono } from "hono";
import { MCPServer } from "mcp-use";

const app = new Hono();
const server = new MCPServer({ name: "hono-app", version: "1.0.0" });

app.all("/mcp", (c) => server.fetch(c.req.raw));
app.all("/mcp/*", (c) => server.fetch(c.req.raw));

export default app;
```

**Deno:**
```typescript
import { MCPServer } from "npm:mcp-use@beta";

const server = new MCPServer({ name: "deno-server", version: "1.0.0" });
// Register tools, resources, prompts

Deno.serve({ port: 3000 }, (req) => {
  if (new URL(req.url).pathname.startsWith("/mcp")) {
    return server.fetch(req);
  }
  return new Response("Not Found", { status: 404 });
});
```

## View asset deployment

**File-based (Node.js, Railway, Bun, Vercel Functions):**
Build outputs `.mcp-use/build/views/`; deploy it alongside server code.

```bash
MCP_URL=https://your-domain.com npm run build
# Deploy: server + .mcp-use/build/views/
```

**Static binding (Cloudflare Workers, edge platforms):**
Mount `.mcp-use/build/views/` as a static asset binding or upload to CDN. Route `/mcp/_mcp-use/views/*` to assets; all other `/mcp` requests to `server.fetch`.

**External CDN:**
```bash
MCP_URL=https://api.example.com \
MCP_ASSETS_URL=https://cdn.example.com/assets \
npm run build
```
Build prints exact CDN path; upload `.mcp-use/build/views/` to that prefix.

## Graceful shutdown

In Node.js or when running `server.listen()`:

```typescript
const { port } = await server.listen(3000);
console.log(`Server at http://localhost:${port}`);

process.on("SIGTERM", async () => {
  await server.close();
  process.exit(0);
});
```

Edge runtimes handle shutdown automatically (no need for explicit cleanup).

See `../08-server-config/07-lifecycle-listen-fetch-shutdown.md` for lifecycle details.
