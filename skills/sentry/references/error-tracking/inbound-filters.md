# Inbound Filters & Dropping Noisy Alerts

How to configure Sentry inbound filters to drop junk errors from web crawlers, browser extensions, legacy browsers, and benign origins.

## Built-In Server-Side Inbound Filters

Sentry provides managed inbound filters under `Project Settings -> Inbound Filters`:

1. **Browser Extensions:** Drops errors caused by known browser extensions (e.g. LastPass, Grammarly, MetaMask injecting scripts).
2. **Known Web Crawlers:** Drops errors triggered by Googlebot, Baiduspider, Bingbot executing broken client JS.
3. **Legacy Browsers:** Drops errors originating from unsupported browsers (IE 10, old Safari).
4. **Localhost:** Drops errors generated by developers testing locally on `http://localhost:*`.

## Client-Side Inbound Filtering (`beforeSend`)

Filter out benign errors client-side before sending an envelope:

```typescript
import * as Sentry from '@sentry/node';

const IGNORED_ERROR_PATTERNS = [
  /ResizeObserver loop limit exceeded/i,
  /Network request failed/i,
  /AbortError: The user aborted a request/i,
  /Load failed for <script>/i,
];

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  beforeSend(event, hint) {
    const error = hint.originalException as Error | undefined;
    if (error && error.message) {
      // Drop ignored patterns
      if (IGNORED_ERROR_PATTERNS.some((pattern) => pattern.test(error.message))) {
        return null; // Returning null drops the event completely
      }
    }

    // Drop 404 Not Found errors
    if (event.tags?.statusCode === '404') {
      return null;
    }

    return event;
  },
});
```

## Muting / Ignoring Issues from the CLI

If an issue is low-priority and you want to mute notifications temporarily:

```bash
# Ignore until it occurs 100 more times:
sentry issue archive <ID> --until count:100

# Ignore for 14 days:
sentry issue archive <ID> --until 14d

# Ignore until seen again in a newer release:
sentry issue archive <ID> --until next_release
```
