# Test Case 09: Same-Day Replacement Confirmation Audit & Cancellation Rollback

## 1. Case ID and Purpose
- **Case ID**: `TC-PLIST-09-SAME-DAY-REPLACE`
- **Purpose**: Verify that initiating an on-demand measurement run when a published measurement already exists for the current UTC day triggers the authoritative same-day replacement workflow, displays the 6-field audit confirmation view with server-issued `confirmationToken`, preserves the identical `intentKey`, and safely rolls back to preview without touching existing published data when cancelled via `rn-confirm-cancel`.

---

## 2. Tester Brief
The tester will:
1. Navigate to the Overview Cockpit at `[APP_URL]/#/[SLUG]/overview` for a project that already has a published measurement run for today.
2. Open the Run modal via `button[data-action="rn-open"]`.
3. Verify that the preview displays the yellow warning banner `"Same-day replacement"`.
4. Click `button[data-action="rn-start"]`.
5. Verify that the server returns `replacement_confirmation_required` and the modal shifts to `view === 'confirm'`:
   - Headline: `"Replace the published measurement?"`
   - Notice: `"The current published data for this day stays visible and unchanged until the new run seals successfully."`
   - Exactly 6 audit fields are displayed: Day, Existing run, Planned cells, Credit cost, Replaces run (`[RUN_ID]`), and Confirmation token (`[REPLACEMENT_TOKEN]`).
6. Click the cancellation button `button[data-action="rn-confirm-cancel"]`.
7. Verify that:
   - The view reverts to `preview`.
   - The existing published measurement run remains completely intact, published, and unaltered.

---

## 3. Inputs and Prerequisites
- **Target Project**: `[SLUG]` (e.g. `daikin`)
- **Initial Route**: `[APP_URL]/#/[SLUG]/overview`
- **Pre-existing State**: A published run for the current UTC day already exists in the database.
- **Dynamic Variables**:
  - `[RUN_ID]`: ID of the existing published measurement run.
  - `[REPLACEMENT_TOKEN]`: Ephemeral token generated by server.

## 5. Visual Checks
1. **Yellow Warning Banner**: `.banner.mt14` renders with yellow tint, question/alert icon, and bold title `"Replace the published measurement?"`.
2. **Audit Table Layout**: `.rank-list` inside `.card.mt8` aligns labels on the left and values on the right with monospace styling for IDs and tokens.
3. **Cancel Button Semantics**: Footer cancel button is styled as neutral secondary button with text `"Cancel — keep the published run"` (Turkish: `"Vazgeç — yayımlı koşu kalsın"`).

## 6. Data and Network Checks
1. **Confirmation Payload Integrity**:
   ```javascript
   const rows = document.querySelectorAll('.rn-modal .rank-list .rrow');
   assert.strictEqual(rows.length, 6, 'Replacement confirmation dialog must render exactly 6 audit rows');

   const replacesRunEl = rows[4].querySelector('.val');
   const tokenEl = rows[5].querySelector('.val');
   assert.ok(replacesRunEl.textContent.trim().length > 10, 'Replaces run ID must be a valid identifier');
   assert.ok(tokenEl.textContent.trim().length > 8, 'Confirmation token must be populated');
   ```
2. **Idempotency Guard**: Verify that `rnCallRunNow(true)` re-uses the exact same `d.intentKey` passed during the initial unconfirmed attempt.
